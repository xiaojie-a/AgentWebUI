agent-mini 定制包（AgentWebUI 专用）安装说明
==========================================

文件清单
--------
  agent_mini-0.3.1+agentwebui.5-py3-none-any.whl 已打好补丁的 agent-mini 0.3.1（纯 Python，跨平台）
  agent-mini-0.3.1-agentwebui.patch              相对官方 0.3.1 的源码补丁（可 git apply）
  SUMMARY.txt                                    逐文件改动统计
  verify_precise_token.py                        精确 Token 全链路验证（直调 provider + 走 bridge）
  verify_numctx_linkage.py                       有效上下文/压缩阈值 是否跟随 numCtx 的验证

  版本说明：本地版本号后缀会随改动递增（.1 → .2 → .3 → .4 → .5）。同名版本重复安装时 pip 会跳过，
  升级请用 `pip install --force-reinstall`（或 `--upgrade`，.3 > .2 会被识别为更新）。


为什么需要这个定制包
--------------------
AgentWebUI 依赖 agent-mini，但官方 0.3.1 直接配 AgentWebUI **在任何操作系统上都会崩**。
按严重程度排：

【故障 1｜硬崩，与操作系统无关 —— 这才是必须用定制版的根本原因】

  agent_bridge.js:495-497 是这样调用 agent-mini 的：

      result = await agent.run(message, conversation,
                                on_stream=on_stream, on_tool_event=on_tool_event,
                                on_thinking=on_thinking)

  而官方 0.3.1 的 AgentLoop.run() 签名只有：

      (self, user_message: str, conversation: list[dict],
       on_stream=None, on_tool_event=None) -> str

  —— 根本没有 on_thinking 这个参数。于是每条消息都在发出后立刻失败：

      TypeError: AgentLoop.run() got an unexpected keyword argument 'on_thinking'

  该异常被 bridge 的 except Exception 捕获，以 {"error": "TypeError: ..."}
  推给前端，表现为"消息一发出去就报错"。

  **Windows / Linux / Termux / macOS 一视同仁，跟编码没有任何关系。**
  已在 Ubuntu + Python 3.14.4 + 官方 pip / pipx 安装版上实测复现。

  这个依赖是 6a246f8（2026-09-10 "更新ui"）引入的；在那之前的版本
  配官方包是可以正常跑的。

【故障 2｜Windows 专属，是额外一层】

  在 locale 编码为 cp936/GBK 的标准 Windows Python 上，
  官方 config.py:126 用 open(CONFIG_FILE) 不带 encoding 读取配置，
  而 ~/.agent-mini/config.json 里面有中文（systemPrompt 等），
  于是 load_config() 直接抛 UnicodeDecodeError，WebUI 起不来。

  实测（PYTHONUTF8=0 模拟标准 Windows）：

    官方写法  -> UnicodeDecodeError: 'gbk' codec can't decode byte 0xa1 ...
    patch 写法 -> 读取成功且内容正确

  注意 1：这一条只在"系统默认编码不是 UTF-8"时成立。Ubuntu 默认
  LANG=zh_CN.UTF-8，所以在 Linux 上它不会发作 —— 别把它当成万能解释。
  注意 2：如果运行时设了 PYTHONUTF8=1（部分环境会），这个问题会被掩盖，
  换一台机器才暴露，所以不要依赖"本机跑得通"。

【故障 3｜静默失效，不报错但功能没了】

  官方 providers/__init__.py 构造 OllamaProvider 时不传 num_ctx，
  于是 WebUI 设置面板里改的"上下文长度 (numCtx)"完全不生效
  （config.json 里写了 numCtx 也会被忽略）。不崩，但设置是假的。

【故障 4、5｜功能性】

  * 思考内容 <think>...</think> 会混进正文一起显示；
  * 工具搜索后端用的是 DuckDuckGo，国内不可达。

【故障 6｜静默降级：前端上下文用量掉回"估算"】

  官方 providers/ollama.py 只在**非流式**的 chat() 里把 prompt_eval_count /
  eval_count 填进 ChatResponse.usage；**流式**的 chat_stream()（WebUI 默认走的
  就是这条）直接
      return ChatResponse(content=..., tool_calls=..., thinking=...)
  不带 usage —— 于是 bridge 的 [精确Token] 取到的永远是 None，
  前端"已用上下文"只能显示"(估算)"，本轮生成/总计两行也不出现。

  patch 做法：在 chat_stream 的 chunk 循环里记录 prompt_eval_count / eval_count
  （ollama 在最后一个 done chunk 里给出），返回时构造 usage 字典交给 ChatResponse。

  实测（xem / Ubuntu / qwen3:1.7b，2026-09-12）：
      直接调 provider.chat_stream -> usage={'prompt_tokens': 16,
                                             'completion_tokens': 182,
                                             'total_tokens': 198}
      走 bridge 全链路 (/task/state) -> usage={'prompt_tokens': 1851, ...}
                                       last_prompt_tokens=1851   ← 真实系统提示量

  注意：这块与【故障 1】无关，缺它只是"少个功能"，不会崩。但**前端的"精确 Token"
  必须配它**：仓库里 agent_bridge.js / public/app.js 已经带 [精确Token] 逻辑，
  如果装的 agent-mini 是旧包，UI 会静默退回估算值。

【故障 7｜静默失效：有效上下文/压缩阈值被档位钉死，跟 numCtx 脱钩】

  官方 agent/token_estimator.py 把"有效上下文"按模型档位写死：

      tiny=3000   small=6000   medium=12000   cloud=32000

  agent/loop.py 用它在会话超过 有效上下文×0.75 时触发摘要压缩（压缩到 ×0.5）。

  于是：**前端滑杆把 numCtx 调到 35840，压缩照样在 6000×0.75=4500 触发**。
  "窗口上限"改了等于没改，实际可用上下文与配置无关（8B 模型被当成 small 档）。

  patch 做法：AgentLoop 构造时优先读 config.providers.<当前 provider>.numCtx
  作为有效上下文（读不到才回退档位默认值），并把压缩比例抽成可配：

      { "agent": { "compactRatio": 0.75, "compactTargetRatio": 0.5 } }

  联动方向：前端「上下文用量」滑杆 -> POST /api/config -> config.numCtx
            -> bridge 下一任务重新 load_config() 建 AgentLoop（**不用重启服务**）

  对照表（compactRatio=0.75）：
      numCtx    有效上下文   压缩阈值
       5120       5120        3840
       8192       8192        6144
      35840      35840       26880
      未设置     档位值       档位值×0.75

  自查：python verify_numctx_linkage.py
        若 numCtx=35840 那行显示 6000/4500，说明装的还是旧包。

【故障 8｜前端"系统提示"蓝色段恒为 0，圆环缺一段】

  官方 agent-mini 的系统提示是 run() 里临时 build_system_prompt() 拼进 messages 的，
  **从不以消息形式存进会话**；而前端上下文圆环的"系统提示（蓝）"段来自对
  role==="system" 会话消息的累加，于是 byType.system 永远为 0，蓝色段被跳过。

  patch 做法：AgentLoop.run() 拼好系统提示后，用与前端同款 CJK 估算公式算出
  self._system_prompt_tokens；bridge 的 done 事件带回 system_prompt_tokens，
  getTaskState 透出；前端 convUsedTokensByType() 末尾累加进 system 段。

  实测（xem / qwen3:1.7b / numCtx 4096）：done 事件
      system_prompt_tokens: 500    ← 真实系统提示估算（约占 prompt 27%）
      last_prompt_tokens:    1851
  硬刷新浏览器后打开上下文圆环弹窗即可看到蓝色"系统提示"段。

  注意：短会话里系统提示 + 工具 schema 确实占 prompt 绝大部分，弹窗按
  ratio=真实/估算 折算后蓝段可能接近 99%，属正确语义，会话变长后按比例缩小。


安装
----
    pip install agent_mini-0.3.1+agentwebui.5-py3-none-any.whl

装进虚拟环境 / 指定目录：

    python -m venv myenv
    myenv/bin/pip install agent_mini-0.3.1+agentwebui.5-py3-none-any.whl

装着旧定制版（+agentwebui / .1 / .2 / .3 / .4）要升级：

    pip install --force-reinstall --no-deps agent_mini-0.3.1+agentwebui.5-py3-none-any.whl

pipx 装的（如 xem）：

    pipx install --force agent_mini-0.3.1+agentwebui.5-py3-none-any.whl

离线机器：把 whl 拷过去，连同依赖一起装（依赖见官方包，主要是 httpx）。


包含的改动（相对 PyPI 官方 0.3.1，共 7 个文件）
----------------------------------------------
  1. config.py                 +3/-3    open() 显式 encoding="utf-8"，
                                       save_config 用 ensure_ascii=False
                                       【Windows 上不加会崩，见上】
  2. providers/ollama.py       +126/-11 两块互相独立的补丁：
                                       (a) [AgentWebUI patch] 增量剥离 <think>…</think>
                                           （标签可跨 chunk 分片，带状态机）；新增
                                           on_thinking 回调（约 160 字合批）；显式
                                           传递 numCtx 控制上下文窗口
                                       (b) [精确Token] 流式 chunk 里提取
                                           prompt_eval_count / eval_count 填进
                                           ChatResponse.usage   【新增，见故障 6】
  3. providers/__init__.py     +1       create_provider 向 OllamaProvider
                                       透传 numCtx          【与 2 必须配对】
  4. agent/loop.py             +127/-12 ① run() 新增 on_thinking 参数并逐层透传
                                       【与 2 必须配对】
                                       ② 有效上下文改为读 numCtx（修故障 7）；
                                          压缩比例 compactRatio / compactTargetRatio
                                          可由 config.agent 覆盖（默认 0.75 / 0.5）
                                       ③ run() 拼好系统提示后用 CJK 公式算
                                          self._system_prompt_tokens，供前端"系统提示"
                                          蓝段显示（修故障 8）
  5. agent/context.py          +17/-1   强制"思考/回复跟随用户语言"；支持
                                       systemPrompt 里的 {{CURRENT_DATE}} /
                                       {{CURRENT_TIME}} 占位替换
  6. agent/tools.py            +152/-132 搜索后端由 DuckDuckGo 换为
                                       Bing CN / Sogou / Baidu（国内可达）
  7. cli.py                    +1/-1    仅 --tools 帮助文案

  重要：这 7 个文件是一个整体，不能只挑几个覆盖。
  __init__.py 会向 ollama.py 传 num_ctx，loop.py 会向 ollama.py 传 on_thinking，
  单独替换其一会出现 TypeError: unexpected keyword argument。


与 AgentWebUI 的关系
--------------------
  agent_bridge.js 会 import agent_mini 的这几个入口：

      from agent_mini.config    import load_config, MEMORY_FILE
      from agent_mini.providers import create_provider
      from agent_mini.agent     import AgentLoop, Memory
      await agent.run(message, conversation,
                      on_stream=..., on_tool_event=..., on_thinking=...)

  前三行的导入在官方包里都存在，所以缺 patch 时"导入阶段"不会报错，
  真正的失败发生在最后一行 —— on_thinking 是 AgentWebUI 自己加的扩展参数，
  官方包没有，必然抛 TypeError（见【故障 1】）。

  换句话说：**官方包 + AgentWebUI = 第一条消息就失败**，
  不是"功能缺失"，是根本用不了。请务必安装本定制包。

  补充（历史遗留）：仓库里还有一份 agent_bridge.py（Python 版桥接），
  它的 run() 调用没有传 on_thinking，所以单看它不会触发【故障 1】；
  但 README 已注明"python 桥街非最新版"，实际在用的是 agent_bridge.js。


从源码重建（不想用 whl 时）
--------------------------
    pip download agent-mini==0.3.1 --no-deps -d am-dl
    cd am-dl
    python -c "import zipfile;zipfile.ZipFile('agent_mini-0.3.1-py3-none-any.whl').extractall('src')"
    cd src
    git apply -p1 ../../agent-mini-0.3.1-agentwebui.patch
    # 然后按正常方式打包/安装

  注：本机 git 若开了 core.autocrlf，apply 后行尾会变成 CRLF，不影响运行。


校验安装是否成功
----------------
    python -c "import agent_mini.config as c, json, tempfile, os, pathlib; \
    p=os.path.join(tempfile.mkdtemp(),'c.json'); \
    open(p,'w',encoding='utf-8').write(json.dumps({'agent':{'systemPrompt':'中文测试'}},ensure_ascii=False)); \
    c.CONFIG_FILE=pathlib.Path(p); \
    print('OK' if c.load_config()['agent']['systemPrompt']=='中文测试' else 'FAIL')"

  打印 OK 即说明中文配置读写正常。

  再验 [精确Token] 补丁在不在（不需要 ollama 正在运行）：

    python -c "import inspect; from agent_mini.providers.ollama import OllamaProvider; \
    s=inspect.getsource(OllamaProvider.chat_stream); \
    print('OK' if 'prompt_eval_count' in s and 'usage=_usage' in s else 'FAIL')"

  打印 OK 表示流式路径会返回真实 usage；FAIL 则前端"已用上下文"只会显示"(估算)"。

  想验得更狠一点（需要 ollama 在跑，会真实推理一次，比较慢）：

    xem 上实测脚本见 WorkBuddy 会话 .workbuddy/tools/verify_precise_token.py
    （A: 直接调 provider.chat_stream 看 usage；B: 走 /chat → /task/<id>/state
      看 last_prompt_tokens。两条都 PASS 才算全链路通。）

  验 [系统提示蓝段]（需要 ollama 在跑，走全链路看 system_prompt_tokens）：

    xem 上发起一次对话后读 /task/<id>/state，确认 system_prompt_tokens > 0。


卸载 / 回滚到官方版
-------------------
    pip uninstall agent-mini
    pip install agent-mini==0.3.1


注意事项
--------
* 本包基于 **0.3.1** 重建。官方若发布新版本，需要重新对 diff 并重建，
  不要直接把本包覆盖到新版本上（RECORD 与代码会不一致）。

* agent-mini 至今没有官方插件机制，本项目对它的改动全部落在上面的 7 个文件里。
  升级 agent-mini 后这些改动会丢失，需要重新打补丁。

* 另有一处**手机专用**改动未并入本包：命中"打开/搜索/截图"等关键词却零工具调用时，
  注入指令强制其调用 phone_control 工具（"零工具调用门禁"）。该逻辑在没有
  phone_control 插件的机器上会误触发，因此只保留在手机端，不进入通用包。
